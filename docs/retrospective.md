# 프로젝트 회고: 분석에서 구조 모델링으로

## 한 줄 회고

이번 한우 등급 예측 프로젝트는 데이터를 많이 붙이고 모델을 돌리는 것만으로는 부족하다는 것을 확인한 프로젝트였다. 핵심은 **한우 등급이 실제로 결정되는 구조를 모델 설계에 반영했는가**였다.

처음에는 `LAST_GRADE`를 하나의 최종 라벨로 두고 16개 클래스를 직접 예측하는 다중분류 문제로 접근했다. 개체 정보, 도축/판정일, 농장/지역 정보, 혈통/KPN 정보, 기상 데이터를 결합했고, CatBoost와 XGBoost 기반 앙상블을 구성했다. C계열 과소예측 문제를 줄이기 위해 확률 보정도 적용했다.

하지만 본선 진출자들의 접근을 비교하면서 차이가 분명해졌다. 우리는 주로 데이터를 결합해 분석하려고 했고, 본선권 접근은 한우 등급이 만들어지는 과정을 분해해 모델 구조로 재현하려고 했다.

```text
우리 접근:
데이터가 있다
→ 전처리한다
→ 결합한다
→ 모델에 넣는다
→ 점수를 올린다

본선권 접근:
한우 등급은 어떤 과정으로 결정되는가?
→ 육질과 육량은 다른 문제인가?
→ 등외 여부를 먼저 판별해야 하는가?
→ 혈통은 단순 ID가 아니라 유전 능력으로 봐야 하는가?
→ 기상은 평균값이 아니라 생애주기별 스트레스 아닌가?
→ 최종 등급은 직접 예측보다 분해 후 합성이 맞지 않은가?
```

## 본선권 접근과의 차이

### 1. 최종 등급 직접 예측 vs 등급 결정 구조 분해

우리는 최종 등급인 `LAST_GRADE`를 바로 예측하는 구조에 가까웠다.

```text
입력 데이터 전체 → CatBoost/XGBoost → LAST_GRADE 16-class
```

반면 본선 진출자들은 대부분 한우 등급 체계를 육질, 육량, 등외 여부, 소수 등급 보정으로 나누어 접근했다.

```text
등외 여부 판별
→ 육질 등급 예측
→ 육량 등급 예측
→ 조합 및 보정
→ 최종 등급 산출
```

이 차이가 가장 컸다. 한우 최종 등급은 단순한 라벨 하나가 아니라 여러 판정 축이 결합된 결과인데, 우리는 이 구조를 모델에게 알아서 학습하라고 맡긴 셈이었다.

### 2. 소수 등급 안정화 전략 부족

평가지표가 Macro-F1이었기 때문에 다수 등급만 잘 맞히는 것으로는 한계가 있었다. 특히 C계열과 등외처럼 표본이 적거나 직접 판정 변수의 영향을 많이 받는 클래스는 별도 전략이 필요했다.

우리는 C계열 과소예측 문제를 확인하고 suffix probability boost를 적용했지만, 본선권은 더 체계적으로 소수 등급을 다뤘다.

- 클래스별 확률 보정
- threshold 조정
- class multiplier
- Coordinate Ascent 기반 확률 최적화
- 등외/소수 등급 전용 모델

즉, 우리는 후처리 단계에서 보정했고, 본선권은 모델 구조와 확률 보정 단계에서 소수 등급을 안정화했다.

### 3. 혈통 정보 활용 방식의 차이

우리는 혈통 데이터를 `CATTLE_NO`, `KPN_NO`, 부모/조부모 계통 정보로 결합하고 빈도 인코딩 및 history feature로 활용했다.

다만 본선권 일부는 혈통을 단순 식별자나 범주형 변수로 보지 않고, **유전 능력 추정값**으로 바꾸어 사용했다. 예를 들어 Animal-Model BLUP 같은 방식은 혈통 관계를 바탕으로 개체의 유전적 잠재력을 수치화하는 접근이다.

```text
우리:
혈통 ID와 KPN 정보를 피처로 결합

더 발전된 접근:
혈통 네트워크 → 유전 능력 추정 → 핵심 입력값으로 사용
```

혈통 데이터는 단순히 붙이는 것보다, 등급에 영향을 주는 유전적 신호로 재가공했을 때 더 강한 피처가 될 수 있었다.

### 4. 기상 정보 활용 방식의 차이

우리는 관측지점과 날짜 기준으로 기상 데이터를 결합하고 최고기온, 최저기온, 강수량, 습도, 풍속 등을 활용했다.

하지만 본선권 접근은 기상을 단순한 날짜별 값이 아니라, 소의 생애주기별 스트레스 지표로 바꾸는 방향이었다.

예를 들어 다음과 같은 파생변수가 더 필요했다.

- 출생 직후 폭염/한파 노출
- 비육 전기 기상 스트레스
- 비육 후기 기상 스트레스
- 도축 전 30일/60일/90일 THI
- 고온다습 동시 발생일 수
- 생애주기별 누적 폭염일수
- 생애주기별 누적 한파일수

결국 기상 데이터는 평균 날씨가 아니라, 성장 과정에서 소가 받은 환경 스트레스로 재해석했어야 했다.

### 5. 검증 설계의 차이

한우 데이터는 같은 농장, 같은 지역, 비슷한 혈통을 공유하는 개체가 많을 수 있다. 일반 랜덤 분할에서는 같은 농장의 패턴이 train과 validation에 동시에 들어가 검증 성능이 실제보다 좋아 보일 수 있다.

본선권 일부는 농장 단위 GroupKFold를 적용해 데이터 누수를 줄였다. 이 방식은 실제 테스트 환경에 더 가까운 검증을 만들 수 있다.

```text
일반 검증:
개체 단위 랜덤 분할

더 보수적인 검증:
FARM_UNIQUE_NO 기준 GroupKFold
```

우리는 제출 성능 개선과 피처 결합에 집중했지만, 검증 단위 자체를 더 엄격하게 설계했어야 했다.

## 이 프로젝트에서 얻은 가장 큰 교훈

이번 프로젝트의 핵심 교훈은 다음 문장으로 정리된다.

> 우리는 데이터를 설명하려 했고, 본선권은 현상이 결정되는 구조를 모델로 재현하려 했다.

처음에는 많은 데이터를 결합하고 모델을 개선하면 점수가 올라갈 것이라고 봤다. 실제로 base 모델 대비 성능 개선은 있었고, C계열 보정이나 1M 모델 학습 같은 시도도 의미가 있었다.

그러나 최종적으로 더 중요한 것은 **타깃이 어떤 과정으로 만들어지는지 이해하고, 그 결정 구조를 모델링하는 것**이었다.

한우 등급 예측은 단순히 `LAST_GRADE`를 맞히는 문제가 아니라 다음과 같은 구조적 문제였다.

```text
육질 관련 신호
+ 육량 관련 신호
+ 등외 여부
+ 혈통/유전 능력
+ 생애주기별 기상 스트레스
+ 농장/지역 이력
= 최종 등급
```

이 구조를 모델링하지 않고 최종 등급을 바로 예측하면, 모델은 복잡한 판정 과정을 한 번에 추정해야 한다. 특히 Macro-F1 환경에서는 소수 등급과 C계열에서 한계가 드러날 수밖에 없다.

## 다시 한다면 설계할 방향

다시 이 문제를 풀었다면 다음과 같이 접근했을 것이다.

```text
1단계: 등외 여부 먼저 분류
2단계: 육질 등급 6-class 예측
3단계: 육량 등급 3-class 예측
4단계: 육질 + 육량 조합으로 최종 등급 후보 생성
5단계: CatBoost / LightGBM / XGBoost / Tabular DL 확률 앙상블
6단계: 클래스별 multiplier 또는 threshold 최적화
7단계: FARM_UNIQUE_NO 기준 GroupKFold로 검증
```

추가로 설계했을 피처는 다음과 같다.

### 혈통 기반 피처

- 아비별 평균 등급
- 어미별 평균 등급
- KPN별 평균 성적
- 조부모 계통별 target encoding
- 혈통 계열별 A/B/C 비율
- 혈통 기반 유전 능력 추정값

### 기상 기반 피처

- 도축 전 30/60/90일 평균 기온
- 생애주기별 THI 평균
- 폭염일수, 한파일수
- 고온다습 동시 발생일
- 출생 직후 기상 스트레스
- 비육 후기 기상 스트레스

### 체중·성장 기반 피처

- `WEIGHT / AGE`
- 성별 대비 체중 z-score
- 농장 대비 체중 z-score
- KPN 대비 체중 z-score
- age bin별 체중 분위
- 성별 × 나이 × 체중 상호작용

## 포트폴리오 관점에서의 정리

이 프로젝트는 높은 성능을 기록한 프로젝트라기보다, 예측 문제를 바라보는 관점을 바꿔준 프로젝트에 가깝다.

기록할 만한 강점은 다음과 같다.

- train/test 변수 차이에 따른 누수 가능성을 확인하고 제거했다.
- test에서 실제 사용 가능한 변수만으로 예측 구조를 재설계했다.
- 지역, 농장, 혈통, KPN, 기상 데이터를 하나의 예측 파이프라인으로 결합했다.
- CatBoost와 XGBoost 확률 앙상블을 구성했다.
- C계열 과소예측 문제를 확인하고 확률 보정을 적용했다.
- 본선권 접근과 비교하며 도메인 결정 구조 기반 모델링의 필요성을 학습했다.

최종 회고는 다음과 같이 정리할 수 있다.

> 처음에는 분석 중심으로 접근했지만, 결과를 비교하면서 예측 문제는 단순히 데이터를 모델에 넣는 것이 아니라 도메인 결정 구조를 모델링하는 관점이 필요하다는 것을 배웠다.

이 문장이 이번 프로젝트의 가장 중요한 결과다.
